# سیاست و مدل امنیتی

<div dir="rtl">

## ۱. مدل تهدید

| دارایی | تهدید | کنترل |
|---|---|---|
| توکن ربات و کلید API | نشت از کد/گیت/لاگ | ذخیره در MySQL با AES-256-GCM، ماسک در UI، عدم لاگ |
| حساب مدیر | Brute force، credential stuffing | Argon2id، قفل ۱۵ دقیقه‌ای بعد از ۵ تلاش، rate limit IP، OTP |
| پنل مدیریت | CSRF، XSS، Clickjacking، Session fixation | CSRF token، escape، CSP/X-Frame-Options، `session_regenerate_id` |
| دیتابیس | SQL Injection | Prepared statements، `EMULATE_PREPARES=false` |
| سرور | SSRF از طریق URL فایل | فقط HTTPS + بررسی IP عمومی + `CURLOPT_PROTOCOLS` |
| کاربران ربات | Spam/Abuse | rate limit ساعتی، مسدودسازی، گیت عضویت |
| داده‌های نصب | بازاجرای نصب‌کننده | `storage/installed.lock` |

## ۲. احراز هویت پنل

```
رمز عبور (Argon2id)
   └─ کد فعال‌سازی یکبارمصرف (فقط اولین ورود / حساب جدید)
        └─ تغییر رمز اجباری
             └─ کد یکبار مصرف (OTP) در هر ورود
```

- کد فعال‌سازی: **هش HMAC-SHA256** در جدول `setup_tokens`، ۲۴ ساعت اعتبار، یک‌بارمصرف، متصل به `admin_id`.
- کد ورود: فقط در سشن سمت سرور، ۱۰ دقیقه اعتبار، حداکثر ۵ تلاش، سپس باطل.
- سشن: `HttpOnly`, `SameSite=Lax`, `Secure` (در HTTPS)، انقضای بی‌کاری ۲ ساعت و حداکثر ۱۲ ساعت، `session_regenerate_id(true)` پس از ورود.
- ابطال سراسری نشست‌ها: با تغییر `session_epoch` همه سشن‌های دیگر باطل می‌شوند.

## ۳. رمزنگاری رازها

```
key = SHA256("settings:" + APP_KEY)
ciphertext = "enc:v1:" + base64(iv[12] || tag[16] || AES-256-GCM(plain))
```

- `APP_KEY` توسط نصب‌کننده به‌صورت ۶۴ کاراکتر hex تصادفی ساخته می‌شود.
- اگر `APP_KEY` تغییر کند، رازها قابل خواندن نیستند (باید دوباره وارد شوند).
- مقادیر رمزنگاری‌شده: `bot_token`, `webhook_secret`, `ig_api_key`, `otp_chat_id`.

## ۴. کنترل‌های ورودی

- لینک اینستاگرام: allow-list دامنه (`instagram.com`, `instagr.am` و زیردامنه‌های مورد انتظار) + الگوی `p|reel|reels|tv`.
- URL فایل: الزام HTTPS، جلوگیری از `user:pass@`، بررسی DNS و بلاک رنج‌های خصوصی/رزرو‌شده:
  `0.0.0.0/8, 10/8, 100.64/10, 127/8, 169.254/16, 172.16/12, 192.0.0/24, 192.168/16, 198.18/15, ::1, fc00::/7, fe80::/10`
- آپلود/دانلود: سقف بایت در حین انتقال، حداکثر ۳ ریدایرکت، تایم‌اوت اتصال و کل.
- فرم‌های پنل: allow-list کلیدها؛ هیچ فیلدی بدون اعتبارسنجی ذخیره نمی‌شود.

## ۵. خروجی امن

- همه مقادیر در قالب با `e()` (htmlspecialchars با `ENT_QUOTES`) چاپ می‌شوند.
- پیام‌های بله با `parse_mode=HTML`؛ نام کاربر، عنوان پست، نام کانال و متن‌های ورودی escape می‌شوند.
- متن خوش‌آمد سفارشی به‌صورت «متن ساده» ارسال می‌شود (نه HTML خام) تا مدیر نتواند تگ تزریق کند.
- URL ها با `FILTER_VALIDATE_URL`/regex بررسی می‌شوند.

## ۶. محدودیت نرخ

| کانون | محدودیت |
|---|---|
| ورود به پنل (IP) | ۱۲ تلاش / ۱۵ دقیقه |
| ورود (نام کاربری) | ۱۰ تلاش / ۱۵ دقیقه |
| بلاک IP | ۲۰ ورود ناموفق / ساعت |
| تأیید OTP | ۱۵ تلاش / ۱۵ دقیقه |
| ارسال دوباره OTP | ۶ / ۱۵ دقیقه |
| دانلود هر کاربر | `rate_limit_per_hour` (پیش‌فرض ۳۰) |
| وبهوک | ۶۰۰ درخواست / دقیقه |

## ۷. پاسخ به رخداد

اگر حس می‌کنید توکن یا رمزی لو رفته است:

1. در بله، توکن ربات را با توکن جدید عوض کنید (از تاپی) و در پنل ذخیره کنید.
2. **امنیت → تغییر رمز عبور** و سپس **ابطال همه نشست‌ها**.
3. **ابزارها → چرخش کلید وب‌هوک** و تنظیم مجدد وب‌هوک.
4. `APP_KEY` را تغییر دهید:
   ```bash
   nano .env      # APP_KEY جدید
   # سپس توکن ربات و کلید API را در پنل دوباره ذخیره کنید
   ```
5. `audit_log` و `login_attempts` را بررسی کنید و IP مشکوک را در `ip_allowlist`/فایروال ببندید.

## ۸. گزارش آسیب‌پذیری

لطفاً آسیب‌پذیری را به‌صورت خصوصی گزارش دهید (نه Issue عمومی). اطلاعات تماس در `SECURITY.md`.

## ۹. نکات استقرار

- `display_errors=Off` و `expose_php=Off` در production.
- DocumentRoot = `public/` (نه ریشه پروژه).
- `storage/` باید قابل نوشتن برای وب‌سرور و **غیرقابل دسترس از وب** باشد.
- `.env` با `chmod 600` و مالک `www-data`.
- بکاپ روزانه دیتابیس + نگهداری ۳۰ روز.
- ورود SSH فقط با کلید، و فایروال فقط پورت‌های 80/443.
